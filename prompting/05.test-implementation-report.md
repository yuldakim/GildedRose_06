**Cursor**

요청하신 테스트 보강 작업을 진행하겠습니다. 먼저 현재 `GildedRose` 구현과 기존 테스트/요구사항을 읽어서, 이미 정의된 동작과 테스트 스타일에 맞춰 추가하겠습니다.

현재 구현은 `Conjured` 규칙을 아직 처리하지 않고, 기존 테스트는 템플릿 상태입니다. 요청대로 아이템 타입별 `TEST_F`를 구성하되, 테스트가 Green이 되도록 최소한의 프로덕션 코드 보정도 함께 하겠습니다.

이제 `GildedRoseTest.cpp`는 fixture 기반의 타입별 경계 테스트로 교체하고, `GildedRose.cpp`는 테스트가 명시하는 `Conjured` 접두어 규칙까지 반영하도록 정리하겠습니다.

테스트와 구현 변경은 적용했습니다. 이제 요청하신 빌드/CTest 흐름으로 실제 컴파일과 테스트 결과를 확인하겠습니다.

`cpp/build`에는 일부 생성물이 있지만 CMake 캐시가 없어 빌드 디렉터리로 인식되지 않습니다. 같은 명령을 루트의 `build` 디렉터리 기준으로도 확인하고, 필요하면 `cpp` 프로젝트를 다시 configure한 뒤 테스트하겠습니다.

빌드 디렉터리를 다시 구성한 뒤 25개 테스트가 모두 통과했습니다. 마지막으로 변경 파일의 IDE 진단을 확인해 새 경고/오류가 없는지 보겠습니다.

IDE 진단은 include path가 CMake/GoogleTest 설정을 따라가지 못해 발생한 것으로 보이며, 실제 CMake 빌드와 CTest는 통과했습니다. 변경 요약만 확인하고 마무리하겠습니다.

완료했습니다.

`cpp/test/GildedRoseTest.cpp`에 `TEST_F` 기반 테스트를 총 25개 추가했습니다.  
Normal / Aged Brie / Backstage Pass / Sulfuras / Conjured 각각 5개씩이고, `quality 0/50`, `sellIn 0/-1` 경계값과 Given-When-Then 주석 구조를 포함했습니다.

`cpp/src/GildedRose.cpp`도 테스트가 Green이 되도록 정리했습니다. 특히 `Conjured` 접두어 아이템은 일반 아이템보다 2배 빠르게 감소하도록 반영했습니다.

검증 결과:

```text
25/25 tests passed
100% tests passed, 0 tests failed out of 25
```

실행한 명령은 `cpp` 디렉터리 기준으로 `cmake -S . -B build`, `cmake --build build`, `ctest --test-dir build --output-on-failure`입니다.  
IDE linter는 CMake include path를 못 잡아 `gtest/gtest.h` 등을 찾지 못한다고 표시하지만, 실제 CMake 빌드와 테스트는 통과했습니다.
