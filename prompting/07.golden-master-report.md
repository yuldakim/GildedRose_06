루트에는 `TexttestFixture.cpp`가 없고 C++ 프로젝트는 `cpp/` 아래에 모여 있습니다. 이제 테스트 디렉터리와 CMake를 확인해 기존 타깃에 Golden Master를 붙일 위치를 정하겠습니다.

현재 `GildedRoseTest.cpp`는 단일 케이스 중심이고, CMake는 테스트 소스 하나만 빌드합니다. Golden Master는 별도 fixture 소스와 approved 출력 파일을 추가하고 같은 테스트 실행 파일에 묶는 구성이 가장 작게 들어맞습니다.

구현 방향은 `TexttestFixture`의 30일치 콘솔 출력을 테스트 내부에서 문자열로 재생성하고, `test/golden-master/*.approved.txt`에 보관한 기준 파일과 바이트 단위로 비교하는 방식입니다. 실패 시 build 디렉터리에 received 파일을 남겨 diff/승인 갱신이 가능하게 하겠습니다.

이제 테스트 소스를 추가하고 CMake가 해당 소스를 빌드하도록 바꾸겠습니다. 기준 출력 파일은 `cpp/test/golden-master` 아래에 두어 소스와 함께 리뷰/버전 관리되게 구성합니다.

기준 파일 생성 스크립트가 PowerShell 인코딩 BOM 때문에 한 번 실패했습니다. 같은 내용을 PowerShell 네이티브 스크립트로 생성해서 파일 인코딩을 안정적으로 맞추겠습니다.

기준 파일은 31개 스냅샷(day 0~30)로 생성됐고, 첫/마지막 출력 형태도 테스트 코드와 맞습니다. 이제 CMake 구성부터 빌드, ctest까지 실제로 돌려서 통합 상태를 확인하겠습니다.

테스트 통합은 빌드까지 성공했고, Golden Master에서 마지막 빈 줄 1개 차이만 발견됐습니다. `TexttestFixture` 출력은 마지막 day 출력 후에도 빈 줄을 하나 더 남기므로 approved 파일을 실제 출력 형식에 맞춰 갱신하겠습니다.

테스트는 26개 모두 통과했습니다. 한 가지 코드 품질상 기준 파일을 못 열 때 즉시 중단되도록 `ASSERT_TRUE` 흐름을 더 명확하게 다듬겠습니다.

구현 완료했습니다. `TexttestFixture.cpp` 파일은 repo에서 찾지 못해, 표준 TexttestFixture의 아이템 세트와 30일 출력 형식을 `cpp/test/GoldenMasterTest.cpp` 안에 재현했습니다.

변경 내용:
- Golden Master 테스트 추가: `cpp/test/GoldenMasterTest.cpp`
- approved 기준 출력 보관: `cpp/test/golden-master/texttest-fixture.approved.txt`
- CMake 통합: `cpp/CMakeLists.txt`에서 새 테스트 소스와 approved/received 경로 주입
- CI 자동 실행 추가: `.github/workflows/cpp-tests.yml`

동작 방식:
- 테스트가 day 0~30의 TexttestFixture 출력 문자열을 생성합니다.
- `texttest-fixture.approved.txt`와 바이트 단위 비교합니다.
- 불일치 시 `cpp/build/texttest-fixture.received.txt`를 생성해 승인 갱신 검토가 가능하게 합니다.
- 의도된 변경이면 received 내용을 approved 파일로 교체하면 됩니다.

실행 방법:

```bash
cd cpp
cmake -S . -B build
cmake --build build --config Release --parallel
ctest --test-dir build --build-config Release --output-on-failure
```

참고로 IDE `ReadLints`는 `gtest/gtest.h` include를 못 찾는 clangd 진단을 표시하지만, 실제 CMake 빌드와 테스트는 정상 통과했습니다.
