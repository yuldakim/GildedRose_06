# Gilded Rose 요구사항 분석

## 1. 아이템 타입별 비즈니스 규칙

| 아이템 타입 | 식별 문자열 | sellIn 변화 | quality 변화 | 경계/예외 |
|---|---|---:|---|---|
| Normal | 기타 일반 아이템 | 매일 -1 | 기본 -1, sellIn 만료 후 -2 | quality는 0 미만 불가 |
| Aged Brie | `Aged Brie` | 매일 -1 | 기본 +1, sellIn 만료 후 +2 | quality는 50 초과 불가 |
| Backstage Pass | `Backstage passes to a TAFKAL80ETC concert` | 매일 -1 | sellIn > 10: +1, 10 >= sellIn > 5: +2, 5 >= sellIn >= 0: +3 | 콘서트 이후 quality = 0, 50 초과 불가 |
| Sulfuras | `Sulfuras, Hand of Ragnaros` | 변화 없음 | 변화 없음 | quality는 예외적으로 80이며 변경하지 않음 |
| Conjured | `Conjured` 계열 아이템 | 매일 -1 | Normal보다 2배 빠르게 감소. 기본 -2, sellIn 만료 후 -4 | quality는 0 미만 불가 |

## 2. 문자열 비교/분기 시 주의점

1. 현재 C++ 구현은 `std::string`의 정확한 문자열 비교(`==`, `!=`)에 의존한다.
2. `Aged Brie`, `Sulfuras`, `Backstage passes`는 요구사항상 고정 이름이므로 `==` 비교가 적합하다.
3. `Conjured`는 신규 카테고리이므로 식별 정책을 명확히 해야 한다.
   - 정확히 이름이 `Conjured`인 아이템만 처리할지
   - `Conjured Mana Cake`처럼 `Conjured`로 시작하는 모든 아이템을 처리할지
4. `std::string::find()` 사용 시 반환값은 `size_t`이며, 찾지 못하면 `std::string::npos`를 반환한다.
5. 다음 패턴은 위험하다.

```cpp
if (name.find("Conjured")) { ... }
```

6. 위 코드는 `Conjured`가 문자열 시작 위치에 있으면 `0`이 반환되어 false가 되고, 찾지 못하면 `npos`가 반환되어 true처럼 동작할 수 있다.
7. `find()`를 사용할 경우 반드시 아래처럼 비교해야 한다.

```cpp
if (name.find("Conjured") != std::string::npos) { ... }
```

8. 접두어 기준이라면 C++17에서는 `starts_with()`가 없으므로 `rfind("Conjured", 0) == 0` 또는 명시적인 헬퍼 함수를 사용한다.

## 3. 예외/경계값 조건

1. `quality`는 일반 아이템, `Aged Brie`, `Backstage Pass`, `Conjured`에 대해 항상 `0 <= quality <= 50`을 유지해야 한다.
2. `quality = 0`인 감소형 아이템은 더 이상 감소하지 않아야 한다.
3. `quality = 50`인 증가형 아이템은 더 이상 증가하지 않아야 한다.
4. `sellIn = 0`은 업데이트 이후 만료 상태가 된다.
5. `sellIn = -1` 및 그 이하 음수는 허용된다. `sellIn`을 0으로 보정하면 안 된다.
6. 일반 아이템은 sellIn 만료 후 하루에 quality가 2 감소한다.
7. `Aged Brie`는 sellIn 만료 후 하루에 quality가 2 증가한다.
8. `Backstage Pass`는 sellIn이 0 미만이 되면 quality가 즉시 0이 된다.
9. `Sulfuras`는 `sellIn`과 `quality` 모두 절대 변경하지 않는다.
10. `Sulfuras`의 quality 80은 일반 quality 상한 50의 예외다.

## 4. Conjured 신규 요구사항

1. `Conjured` 아이템은 일반 아이템보다 quality가 2배 빠르게 감소한다.
2. 판매 기한 전에는 하루에 quality가 2 감소한다.
3. 판매 기한이 지난 후에는 일반 아이템의 만료 후 감소량도 2배가 되어 하루에 quality가 4 감소한다.
4. quality는 0 미만으로 내려가면 안 된다.
5. `Conjured`는 `Sulfuras`, `Aged Brie`, `Backstage Pass`보다 낮은 우선순위의 별도 타입으로 분기하는 것이 안전하다.
6. 구현 전 `Conjured` 식별 규칙을 확정해야 한다.
   - 권장: 이름이 `Conjured`로 시작하는 아이템을 Conjured 카테고리로 처리

## 5. Google Test 테스트 시나리오 목록

1. Normal 아이템은 하루 후 `sellIn`이 1 감소하고 `quality`가 1 감소한다.
2. Normal 아이템은 `sellIn = 0`에서 업데이트 후 `sellIn = -1`, `quality`가 2 감소한다.
3. Normal 아이템의 `quality = 0`은 감소하지 않는다.
4. Aged Brie는 하루 후 `sellIn`이 1 감소하고 `quality`가 1 증가한다.
5. Aged Brie는 `sellIn = 0`에서 업데이트 후 `quality`가 2 증가한다.
6. Aged Brie의 `quality = 50`은 증가하지 않는다.
7. Backstage Pass는 `sellIn > 10`일 때 `quality`가 1 증가한다.
8. Backstage Pass는 `sellIn = 10`일 때 `quality`가 2 증가한다.
9. Backstage Pass는 `sellIn = 5`일 때 `quality`가 3 증가한다.
10. Backstage Pass는 `sellIn = 0`에서 업데이트 후 `quality = 0`이 된다.
11. Backstage Pass는 증가하더라도 `quality = 50`을 초과하지 않는다.
12. Sulfuras는 업데이트 후에도 `sellIn`과 `quality`가 모두 변하지 않는다.
13. Sulfuras의 `quality = 80`은 50으로 보정하지 않는다.
14. Conjured 아이템은 판매 기한 전 하루에 `quality`가 2 감소한다.
15. Conjured 아이템은 `sellIn = 0`에서 업데이트 후 `quality`가 4 감소한다.
16. Conjured 아이템의 `quality`는 0 미만으로 내려가지 않는다.
17. 여러 아이템이 함께 있을 때 각 아이템 타입별 규칙이 독립적으로 적용된다.
```
