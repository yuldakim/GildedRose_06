# Gilded Rose 결함 분석 보고서

## 1. 작성 목적

이 보고서는 `GildedRose::updateQuality()` 테스트 구현 및 검증 과정에서 확인된 결함과 잔여 리스크를 QA 관점에서 정리하기 위해 작성했다.

결함 원본 목록은 `docs/defect_list.md`를 기준으로 하며, 테스트 대상은 C++17 기반 `cpp/src/GildedRose.cpp`와 Google Test 기반 `cpp/test/GildedRoseTest.cpp`이다.

## 2. 검증 범위

검증 대상 아이템 타입은 다음과 같다.

1. Normal
2. Aged Brie
3. Backstage Pass
4. Sulfuras
5. Conjured

각 아이템 타입에 대해 `sellIn`, `quality`, 품질 상한/하한, 판매 기한 경계값을 중심으로 검증했다.

## 3. 현재 테스트 상태

현재 `cpp/build` 기준 CTest 결과는 Green이다.

```text
100% tests passed, 0 tests failed out of 25
```

즉, 현재 코드 기준으로 재현 중인 기능 테스트 실패는 없다. 다만 테스트 구현 과정에서 발견된 결함과 실행 환경상 주의해야 할 빌드 경로 이슈는 결함 목록으로 기록했다.

## 4. 결함 요약

| ID | Severity | ItemType | 상태 | 요약 |
|---|---|---|---|---|
| DEF-001 | Major | Conjured | Resolved | 판매 기한 전 Conjured 아이템이 일반 아이템처럼 1만 감소하던 결함 |
| DEF-002 | Major | Conjured | Resolved | 판매 기한 당일/이후 Conjured 아이템이 4가 아닌 2만 감소하던 결함 |
| DEF-003 | Minor | Build/Test Infrastructure | Open/Documented | 저장소 루트의 `build` 디렉터리가 유효한 CMake 빌드 디렉터리가 아닌 문제 |

## 5. 결함 상세 분석

### DEF-001: Conjured 판매 기한 전 감소량 오류

Severity는 `Major`로 분류했다. 신규 요구사항인 Conjured 규칙이 적용되지 않으면 실제 상품 가치 계산 결과가 요구사항과 다르게 산출되기 때문이다.

재현 조건은 `Item("Conjured", 10, 20)`을 생성한 뒤 `updateQuality()`를 1회 호출하는 것이다.

기대 결과는 `sellIn = 9`, `quality = 18`이다. Conjured 아이템은 일반 아이템보다 두 배 빠르게 품질이 감소해야 하므로 판매 기한 전 감소량은 2가 되어야 한다.

수정 전 실제 결과는 `quality = 19`였으며, 이는 Conjured 아이템이 일반 아이템 분기로 처리되었기 때문이다.

수정 요약은 다음과 같다.

1. 아이템 이름이 `Conjured`로 시작하는지 판별한다.
2. Conjured 아이템의 기본 감소량을 2로 계산한다.
3. `decreaseQuality()` 헬퍼를 통해 품질이 0 미만으로 내려가지 않도록 보정한다.

### DEF-002: Conjured 판매 기한 경계값 감소량 오류

Severity는 `Major`로 분류했다. 판매 기한 당일과 이후는 품질 감소량이 커지는 핵심 경계 조건이며, 이 조건에서 Conjured 규칙이 누락되면 재고 가치가 지속적으로 과대평가된다.

재현 조건은 `Item("Conjured", 0, 20)`을 생성한 뒤 `updateQuality()`를 1회 호출하는 것이다.

기대 결과는 `sellIn = -1`, `quality = 16`이다. Conjured 아이템은 기본적으로 2 감소하고, 판매 기한이 지난 조건에서는 그 두 배인 4가 감소해야 한다.

수정 전 실제 결과는 `quality = 18`이었으며, 이는 일반 만료 아이템의 감소량 2만 적용되었기 때문이다.

수정 요약은 다음과 같다.

1. Conjured 기본 감소량을 먼저 계산한다.
2. `sellIn <= 0`이면 계산된 기본 감소량을 다시 두 배로 적용한다.
3. `quality = 0` 하한은 공통 감소 헬퍼에서 보장한다.

### DEF-003: 루트 빌드 디렉터리 실행 오류

Severity는 `Minor`로 분류했다. 제품 기능 결함은 아니지만, 잘못된 경로에서 테스트 명령을 실행하면 검증 절차가 중단될 수 있기 때문이다.

저장소 루트에서 다음 명령을 실행하면 실패한다.

```powershell
cmake --build build
```

실제 오류는 다음과 같다.

```text
Error: not a CMake build directory (missing CMakeCache.txt)
```

원인은 활성 CMake 프로젝트와 유효한 빌드 디렉터리가 `cpp/build`에 있기 때문이다. 따라서 저장소 루트 기준 검증 명령은 다음과 같이 실행해야 한다.

```powershell
cmake --build cpp/build
ctest --test-dir cpp/build --output-on-failure
```

또는 `cpp` 디렉터리로 이동한 뒤 다음 절차를 사용할 수 있다.

```powershell
cmake --build build
ctest --test-dir build --output-on-failure
```

## 6. 수정 결과

현재 `cpp/src/GildedRose.cpp`는 Conjured 접두어 판별을 통해 `Conjured`와 `Conjured Mana Cake` 같은 아이템을 Conjured 계열로 처리한다.

핵심 수정 내용은 다음과 같다.

1. `isConjured()`로 `Conjured` 접두어를 판별한다.
2. 일반 아이템 감소량은 1, Conjured 감소량은 2로 분리한다.
3. 판매 기한 당일 또는 이후에는 감소량을 두 배로 적용한다.
4. `std::max`와 `std::min` 기반 헬퍼로 품질 하한 0, 상한 50을 보장한다.
5. `Sulfuras`는 조기 `continue`로 `sellIn`과 `quality` 모두 변경하지 않는다.

## 7. Green 확인 절차

저장소 루트에서 다음 명령을 실행한다.

```powershell
cmake --build cpp/build
ctest --test-dir cpp/build --output-on-failure
```

기대 결과는 다음과 같다.

```text
100% tests passed, 0 tests failed out of 25
```

## 8. QA 결론

현재 기능 테스트 기준으로 남아 있는 `updateQuality()` 결함은 없다.

Conjured 관련 주요 결함 2건은 테스트로 재현 가능한 형태로 고정되었고, 현재 구현에서 모두 해결되었다. 남은 주의 사항은 빌드/테스트 실행 위치에 관한 인프라성 이슈이며, 검증 절차 문서화를 통해 회피 가능하다.
