# Gilded Rose Golden Master 회귀 테스트 보고서

## 1. 작성 목적

이 보고서는 `TexttestFixture` 출력 기반 Golden Master 회귀 테스트의 설계, 구현 방식, 빌드 통합, CI 자동 실행 구성을 QA 관점에서 정리하기 위해 작성했다.

테스트 대상은 C++17 기반 `GildedRose::updateQuality()`이며, 기존 단위 테스트가 개별 규칙을 검증하는 것과 별도로 다일자 출력 전체를 기준 파일과 비교해 예기치 않은 동작 변화를 탐지하는 것을 목표로 했다.

## 2. 구현 대상

1. 테스트 코드: `cpp/test/GoldenMasterTest.cpp`
2. 기준 출력 파일: `cpp/test/golden-master/texttest-fixture.approved.txt`
3. CMake 설정: `cpp/CMakeLists.txt`
4. CI 설정: `.github/workflows/cpp-tests.yml`
5. 비교 대상 인터페이스: `cpp/include/GildedRose.h`, `cpp/include/Item.h`
6. 비교 대상 구현: `cpp/src/GildedRose.cpp`

## 3. Golden Master 설계 전략

Golden Master는 `TexttestFixture`의 콘솔 출력 형식을 테스트 내부에서 재현한 뒤, 해당 출력 전체를 approved 파일과 비교하는 방식으로 설계했다.

출력 범위는 day 0부터 day 30까지 총 31개 스냅샷이다. 각 day는 다음 구조를 가진다.

```text
-------- day N --------
name, sellIn, quality
<item name>, <sellIn>, <quality>
```

기준 파일은 `cpp/test/golden-master/texttest-fixture.approved.txt`에 보관한다. 이 파일은 소스 코드와 함께 버전 관리되어야 하며, 의도된 동작 변경이 있을 때만 리뷰 후 갱신한다.

테스트 실패 시 실제 출력은 `cpp/build/texttest-fixture.received.txt`에 생성된다. 이 received 파일은 빌드 산출물이므로 커밋 대상이 아니며, approved 파일 갱신 여부를 판단하기 위한 검토 자료로 사용한다.

## 4. 테스트 데이터 구성

테스트 데이터는 표준 `TexttestFixture` 시나리오에 Conjured 항목을 포함해 구성했다.

1. `+5 Dexterity Vest`
2. `Aged Brie`
3. `Elixir of the Mongoose`
4. `Sulfuras, Hand of Ragnaros`
5. `Backstage passes to a TAFKAL80ETC concert`
6. `Conjured Mana Cake`

이 구성은 Normal, Aged Brie, Backstage Pass, Sulfuras, Conjured 규칙을 하나의 장기 실행 출력으로 함께 검증한다.

## 5. Google Test 구현 방식

`GoldenMasterTest.TexttestFixtureOutputMatchesApprovedFile` 테스트는 다음 순서로 동작한다.

1. `texttest-fixture.approved.txt`를 바이너리 모드로 읽는다.
2. 테스트 내부에서 TexttestFixture 출력 문자열을 생성한다.
3. expected와 actual을 문자열 전체 비교한다.
4. 불일치하면 `texttest-fixture.received.txt`를 빌드 디렉터리에 남긴다.
5. Google Test 실패 메시지에 approved/received 경로를 출력한다.

핵심 검증은 `EXPECT_EQ(expected, actual)`로 수행한다. 문자열 전체 비교를 사용하므로 특정 아이템의 값뿐 아니라 출력 순서, day 헤더, 줄바꿈 변화까지 회귀로 감지할 수 있다.

approved 파일을 열지 못하는 경우에는 `ASSERT_TRUE`로 즉시 실패하도록 했다. 기준 파일이 없거나 경로가 잘못된 상태에서 빈 문자열 비교로 오탐이 발생하지 않게 하기 위한 조치다.

## 6. CMake 및 CTest 통합

`cpp/CMakeLists.txt`는 기존 `gilded_rose_test` 실행 파일에 `GoldenMasterTest.cpp`를 함께 빌드하도록 수정했다.

```cmake
add_executable(gilded_rose_test
    test/GildedRoseTest.cpp
    test/GoldenMasterTest.cpp
)
```

approved/received 경로는 CMake compile definition으로 주입한다.

```cmake
target_compile_definitions(gilded_rose_test PRIVATE
    GOLDEN_MASTER_APPROVED_FILE="${CMAKE_CURRENT_SOURCE_DIR}/test/golden-master/texttest-fixture.approved.txt"
    GOLDEN_MASTER_RECEIVED_FILE="${CMAKE_CURRENT_BINARY_DIR}/texttest-fixture.received.txt"
)
```

이 방식은 테스트 코드에 상대 경로 탐색 로직을 넣지 않아도 되며, 빌드 디렉터리 위치가 달라져도 approved 파일과 received 파일의 위치가 명확하게 유지된다.

`gtest_discover_tests(gilded_rose_test)`를 그대로 사용하므로 Golden Master 테스트는 CTest에 자동 등록된다.

## 7. CI 자동 실행 구성

GitHub Actions 워크플로는 `.github/workflows/cpp-tests.yml`에 추가했다.

워크플로는 `push`와 `pull_request`에서 실행되며, Ubuntu 환경에서 다음 단계를 수행한다.

1. 저장소 checkout
2. `cpp` 디렉터리에서 CMake configure
3. CMake build
4. CTest 실행

CI에서 실행하는 명령은 다음과 같다.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
ctest --test-dir build --build-config Release --output-on-failure
```

Golden Master가 실패하면 `--output-on-failure` 옵션으로 Google Test 실패 메시지가 CI 로그에 출력된다. 이를 통해 어떤 approved 파일을 검토해야 하는지 확인할 수 있다.

## 8. 실행 및 승인 갱신 방법

로컬 실행 절차는 다음과 같다.

```powershell
cd cpp
cmake -S . -B build
cmake --build build --config Release --parallel
ctest --test-dir build --build-config Release --output-on-failure
```

테스트가 실패했지만 동작 변경이 의도된 경우에는 다음 절차로 승인 파일을 갱신한다.

1. `cpp/build/texttest-fixture.received.txt` 내용을 검토한다.
2. 변경이 요구사항과 일치하는지 확인한다.
3. `cpp/test/golden-master/texttest-fixture.approved.txt`를 received 내용으로 교체한다.
4. CTest를 다시 실행해 Green 상태를 확인한다.
5. 변경된 approved 파일을 테스트 코드 변경과 함께 리뷰한다.

의도되지 않은 변경이라면 approved 파일을 갱신하지 않고 `GildedRose::updateQuality()` 구현을 수정해야 한다.

## 9. 검증 결과

최종 검증은 `cpp` 디렉터리에서 빌드 후 CTest로 수행했다.

```text
100% tests passed, 0 tests failed out of 26
```

기존 단위 테스트 25개에 Golden Master 테스트 1개가 추가되어 총 26개 테스트가 실행된다.

## 10. 잔여 리스크

IDE linter는 CMake가 내려받은 Google Test include path를 인식하지 못해 `gtest/gtest.h` 관련 진단을 표시할 수 있다. 그러나 CMake configure, build, CTest 기준으로는 컴파일과 테스트가 모두 통과했다.

Golden Master 테스트는 출력 전체의 회귀 탐지에는 강하지만, 실패 원인을 세밀하게 설명하는 데에는 단위 테스트보다 불리하다. 따라서 현재처럼 개별 규칙은 `GildedRoseTest.cpp`에서 검증하고, 장기 출력 회귀는 `GoldenMasterTest.cpp`에서 보호하는 이중 전략을 유지하는 것이 적절하다.

## 11. QA 결론

이번 구현으로 `TexttestFixture` 기반 장기 실행 출력이 approved 파일로 고정되었다. 이후 리팩터링이나 신규 아이템 규칙 추가 시 출력 전체의 의도하지 않은 변화가 CTest와 CI에서 자동으로 탐지된다.

Golden Master는 기존 단위 테스트를 대체하지 않고 보완한다. 단위 테스트는 규칙별 원인 분석을 담당하고, Golden Master는 전체 시스템 동작의 스냅샷 회귀 방어를 담당하므로 Gilded Rose 레거시 코드의 안전한 변경 기반이 강화되었다.
