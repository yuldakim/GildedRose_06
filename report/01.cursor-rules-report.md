# Gilded Rose Cursor AI 규칙 작성 보고서

## 1. 작성 목적

이 보고서는 Gilded Rose C++17 레거시 코드베이스에서 Cursor AI가 일관된 기준으로 QA와 리팩토링을 수행하도록 프로젝트 루트의 `.cursorrules` 파일에 정의한 규칙을 정리한 문서이다.

Gilded Rose는 레거시 리팩토링 카타 성격의 프로젝트이므로, 기존 동작 보존과 테스트 기반 변경이 가장 중요하다. 특히 `Item` 구조체는 외부 계약으로 간주하고 수정하지 않아야 하며, 상품 품질과 판매 기한에 대한 도메인 제약을 모든 작업에서 유지해야 한다.

## 2. 적용 기술 스택

- 언어 표준: C++17
- 빌드 시스템: CMake
- 테스트 프레임워크: Google Test
- 커버리지 도구: gcov/lcov

## 3. 절대 준수 규칙

- `Item` 구조체와 공개 필드는 수정하지 않는다.
- `quality` 값은 `Sulfuras`를 제외하고 항상 0 이상 50 이하를 유지한다.
- `Sulfuras`는 `sellIn`과 `quality`가 절대 변경되지 않는다.
- `sellIn`은 음수가 될 수 있으므로, 음수 값을 막거나 0으로 보정하지 않는다.

이 규칙들은 도메인 불변식에 해당하므로 리팩토링, 테스트 추가, 기능 변경 작업 모두에서 우선적으로 지켜야 한다.

## 4. 테스트 작성 기준

- 테스트는 Given-When-Then 구조를 선호한다.
- fixture가 필요한 경우 `TEST_F`를 사용한다.
- 동작 변경이나 리팩토링 전후에는 경계값 테스트를 포함한다.
- 필수 경계값은 `quality = 0`, `quality = 50`, `sellIn = 0`, `sellIn = -1`이다.
- 테스트는 `updateQuality()` 실행 이후 관찰 가능한 `Item` 상태를 기준으로 검증한다.

## 5. 리팩토링 기준

- 전체 테스트가 Green인 상태에서만 리팩토링을 진행한다.
- 명시적인 요구가 없는 한 기존 동작을 보존한다.
- 작은 단위의 동작 보존 변경을 우선한다.
- 복잡한 추상화보다 명확한 이름과 단순한 제어 흐름을 선호한다.
- 의미 있는 경우 매직 넘버를 이름 있는 상수로 치환한다.
- 충분한 특성화 테스트 없이 대규모 재작성은 진행하지 않는다.

## 6. 기대 효과

`.cursorrules`를 통해 Cursor AI는 Gilded Rose 프로젝트의 핵심 제약을 항상 참고할 수 있다. 이를 통해 `Item` 구조체 수정, 품질 범위 위반, `sellIn` 음수 처리 오류 같은 대표적인 회귀를 줄이고, 테스트 기반의 안전한 리팩토링 흐름을 유지할 수 있다.
