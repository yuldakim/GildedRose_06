# Conjured 아이템 기능 구현 보고서

## 1. 작업 개요

Gilded Rose C++17 프로젝트에 `Conjured` 아이템 규칙을 반영했다. `Item` 구조체와 공개 필드는 변경하지 않았고, 기존 `GildedRose::updateQuality()` 흐름 안에서 이름 기반 분기로 처리했다.

적용 규칙은 다음과 같다.

| 조건 | `quality` 변화 | 비고 |
|---|---:|---|
| `Conjured` 아이템, `sellIn >= 0` | -2 | 매일 일반 아이템보다 2배 빠르게 감소 |
| `Conjured` 아이템, `sellIn < 0` | -4 | 기한 경과 후 2배 추가 감소 |
| 감소 후 `quality < 0` | 0으로 보정 | 최소 품질 0 유지 |

## 2. 구현 내용

`cpp/src/GildedRose.cpp`에서 `Conjured` 접두어 판별을 유지하면서, `Conjured` 전용 감소 규칙을 일반 아이템 분기와 분리했다.

- `Conjured`는 `item.name.rfind("Conjured", 0) == 0`으로 판별한다.
- `sellIn < 0`이면 `quality`를 4 감소시킨다.
- 그 외 `Conjured` 아이템은 `quality`를 2 감소시킨다.
- `decreaseQuality()`를 통해 `quality`가 0 미만으로 내려가지 않도록 보장한다.
- `Item` 구조체는 수정하지 않았다.

## 3. 테스트 변경

`cpp/test/GildedRoseTest.cpp`의 `Conjured` 경계 테스트를 요구사항 기준에 맞게 조정했다.

- 판매 기한 전 `Conjured` 아이템은 `quality -2`를 검증한다.
- `sellIn = 0`에서는 아직 `sellIn < 0`이 아니므로 `quality -2`를 검증한다.
- `sellIn = -1`에서는 기한 경과 후 규칙으로 `quality -4`를 검증한다.
- `quality = 0` 및 `Conjured` 접두어 아이템의 하한 보정을 검증한다.

## 4. 검증 결과

요청한 빌드 및 테스트 검증을 수행했다.

```text
cmake --build build && ctest
```

Windows PowerShell 환경에서 `cpp` 빌드 디렉터리를 기준으로 동일한 검증 흐름을 실행하기 위해 다음 명령을 사용했다.

```text
cmd /c "cmake --build build && ctest --test-dir build --output-on-failure"
```

결과:

```text
100% tests passed, 0 tests failed out of 26
```

## 5. 결론

`Conjured` 기능은 `Item` 구조체 변경 없이 구현되었고, `sellIn < 0` 이후 `quality -4`, 그 외 `quality -2`, 최소 품질 0 규칙을 만족한다. CMake 빌드와 CTest 전체 테스트는 Green 상태다.
